# مصادر AMANAH — القرآن والحديث والتفسير

> قاعدة المشروع: إذا نصت الحزمة العلمية الرسمية للتحدي على مصدر معتمد في مجال ما، فهي المرجع الأول. المصادر الخارجية أدناه موثوقة تقنيًا/علميًا للاستخدام، لكن لا نسمّيها "معتمدة من التحدي" إلا إذا وردت في الحزمة.

## 1) النص العربي للقرآن
**King Fahd Glorious Qur'an Printing Complex (KFGQPC)**
- الاستخدام: canonical Arabic source.
- الأفضل تنزيل الحزمة الرسمية وتخزينها محليًا في backend بدل استدعاء API خارجي لكل طلب.
- ملف manifest في: `sources/official_source_manifest_v02.json`.
- Notebook يتحقق من checksum قبل بناء البيانات.

## 2) ترجمات معاني القرآن الإنجليزية
**QuranEnc API**
- Public API بدون API key في الواجهات الموثقة.
- نستخدم أكثر من ترجمة مرجعية عند المقارنة، ونحفظ `translation_key` و`version` وURL وتاريخ الجلب.
- لا نعدل نص الترجمة المرجعية.
- لا تعني الترجمة المرجعية وحدها أن candidate خاطئ إذا اختلف الأسلوب؛ القرار يجب أن يركز على المعنى المحمي.

## 3) الحديث
**Dorar Al-Sunniah Hadith API**
- Endpoint الموثق: `https://dorar.net/dorar_api.json?skey=...`
- لا يوجد مفتاح API في التوثيق العام الحالي.
- الاستخدام: retrieval + إظهار المصدر والحكم/الدرجة القابلة للتتبع.
- AMANAH يمتنع إذا لم يمكن إثبات المصدر والحكم والرابط؛ لا نخمن درجة الحديث.

## 4) التفسير
### KFGQPC — التفسير الميسر
- الأفضل كـ dataset محلي موثوق مع فصل `aya_text` عن `aya_tafseer`.
- يخدم RAG/context ولا يُدمج كلام التفسير مع نص القرآن.

### Dorar Tafsir
- مرجع قوي للمراجعة البشرية، والتقرير الخاص بالمشروع أحال إليه.
- لم نتحقق من REST API عام موثق للتفسير؛ لذلك لا نعتمد scraping غير موثق داخل الإنتاج.
- يمكن الربط بالرابط للمراجع البشري، أو بناء طبقة API داخلية فوق dataset رسمي مرخص/متاح.

## الاستخدام الصحيح للمشروع
- Quran Arabic = canonical truth source.
- QuranEnc = reference translations.
- Hadith/Tafsir = evidence/context/retrieval.
- لا نستخدم الحديث أو التفسير كـ "مترجم" للآية.
- لا نغيّر عقد AMANAH API بسبب إضافة المصادر.
